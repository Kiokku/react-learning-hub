提出问题 → 探索 → 验证 → 沉淀

从 路线图 选一个当前想理解的机制，再找到关联课程章节。以“提出问题 → 学习探索 → 独立验证 → 画布沉淀”为基本方法；复杂机制可跨多次学习，简单配置可以直接验证后继续。

1. 提出问题

在章节画布放下一个问题或预测。例如：“JSX 编译后是什么？为什么此时还没有 DOM？”先说清楚自己的判断和不确定之处，再打开课程或向 AI 提问。

理解设计时，可以追问：遇到了什么问题？直接方案有什么局限？采用了什么机制？它换来了什么，又付出了什么代价？这些是思考线索，不是必填字段。

2. 学习探索

结合课程、指定版本源码和文档寻找依据。AI 可以帮忙解释、提出反例和定位源码；保存值得回访的问答，保留原问题、章节和来源上下文。

CourseX 已有课节问答和 tldraw 画板可供使用。主画布自动恢复、保存对话与知识卡片入口需要以实际版本为准：入口可用时主动保存；尚未提供时手动将关键片段和出处放到已有画板，记住该章使用的画板。不需要额外建立 Markdown 日志。

NotebookLM、teach 和流程图工具按需使用，不是前置依赖。不要让 AI 在你理解设计前直接生成 Reconciler、Hooks、Diff、Lane 或 Suspense 的完整实现。

3. 独立验证

先预测结果，再通过 mini React 最小实现、行为测试、反例实验或可信的源码依据确认关键行为。实现与测试放在独立的 mini-react18 仓库。尝试改变一个条件，观察行为是否符合解释，并记录理解发生了什么修正。

核对课程简化实现、自己的实现和指定版本的 React 官方实现。引用源码时留下 tag 或 commit 与文件位置；测试留下条件、预期和结果。React 19/19.2 补充主题以实际版本的 Demo 和对比为主，不要求移植进 mini React。

4. 画布沉淀

用自己的话留下结论、必要图解、证据链接，以及尚未确定的边界。内容以未来能恢复理解为准，不要求固定模板、卡片数量、Quiz 或面试回答。

保存原始对话与提炼知识结论是两种操作。AI 提炼内容先作为可编辑草稿；“待验证 / 已验证”可用轻量标记表达，作者自行核查依据，不设置审批流程。不要把每条 AI 回复自动堆进画布。

一次机制探索的最小完成条件：你能脱离课件解释核心机制，关键判断有源码、测试或独立实验支持，画布内容足以让以后快速恢复理解。遇到反例可以继续修正，无需维护另一套状态表。
