PRODUCT STRATEGY/ React Learning Hub × CourseX / v1.0
2026.11.05 · PRODUCT PROPOSAL · V1.0

从源码学习，
走向可生长的知识作品。

React Learning Hub 不再是一套沉重的学习管理系统，而是 CourseX 上学习 React 的路线图与说明书；CourseX 不再只是播放器加笔记区，而是以「章节无限画布」承载知识卡片、AI 对话、实验记录和图解的学习创作空间。所有知识成果支持 Git 友好的结构化导出，最终服务于 React, Explained. 交互式深度教材。

产品状态：企划 / 待开发两项目协同不迁移旧学习记录优先单用户、本地优先
方案总原则：说明书负责指路，CourseX 负责学习，画布负责沉淀，Git 负责可拥有，最终作品负责对外表达。

01 / POSITIONING & BASELINE

两个项目的边界现在应当比之前更清晰：一个提供学习路径，一个承载学习行为与成果。公开教材是未来产物，而不是本轮改造的交付范围。

B01 · 章节主画布
P0

章节 ↔ 主画布稳定绑定

  • 打开课程章节，能找到对应的同一张主画布；没有时按需创建。
  • 持久化 courseId / chapterId / canvasId 关系，防止重复创建。
  • 切换章节时恢复原有节点、视口与最近编辑内容；提供“聚焦画布”。
  • 保留已有画板选择能力，允许额外草稿画板，但默认主画布清晰可辨。

验收：多次打开同一章节不生成重复主画布，切换与刷新后内容不丢失。

B02 · 知识卡片
P0

在画布中保存简洁、可编辑的知识内容

  • 支持普通文本卡片、问题卡片、结论卡片及代码/来源链接卡片；优先通过 tldraw 自定义 Shape 或已有文本形状扩展。
  • 卡片拥有稳定 ID、标题、正文、创建/修改时间及引用；允许自由布局与连接。
  • 可从选中的课件文字、AI 对话中创建草稿卡片；用户可修改和删除。
  • “待验证 / 已验证”是可选的轻量标记，不要求填写复杂知识模板。

验收：新增、编辑、移动、重新打开、导出后均可读取完整卡片内容。

B03 · AI → 画布
P0

把对话从一次性问答变成可复用素材

  • 在已有课节问答中增加 保存到画布，支持单轮问答或用户选中的片段。
  • 保存为“对话卡片”时，至少保留问题、回答、时间、原始会话引用、关联章节与来源上下文。
  • 提供“提炼为知识卡片”操作，但默认进入可编辑草稿，不自动宣称答案已验证。
  • 用户主动保存，避免每条聊天消息自动进入画布造成信息噪声。

验收：同一问答能被保存、回看、引用；重启后仍可阅读，AI 回答不会未经确认就变成知识结论。

B04 · 证据引用
P0

把重要解释与源码/测试联系起来

  • 卡片可关联课程章节、URL、Git commit、代码文件路径、React 版本或测试结果。
  • 记录“来源类型”和可选版本信息，避免混淆课程 mini React 与 React 官方源码。
  • 画布里的代码引用应是可点击的资源链接，而不是复制整段付费课程材料。

验收：一个“已验证”卡片能追溯至少一条用户记录的测试或可信源码证据；具体要求由作者决定，不设强制审核审批流程。

B05 · 跨章节引用
P1

建立知识网络，而不是复制相同卡片

支持在画布中引用其他章节卡片，打开链接可跳转到目标章节并定位对应节点。MVP 可先实现只读“卡片链接”节点，不必做全局知识图谱。

验收：从 Fiber 章节点击 ReactElement 引用，可进入 JSX 章节并定位目标卡片。

B06 · 画布聚焦与整理
P1

用画布完成学习，而不是制造另一套 UI

提供“插入问题 / 插入卡片 / 保存对话 / 插入证据”的快捷动作、按对象定位、适度的框架和分区。不要强制生成四栏模板或限定卡片布局；无限画布的自由度是产品特征。

B07 · 高级交互组件
P2

为未来 React 图解积累组件能力

在知识画布中逐渐支持可执行的 Fiber 树、Hook 链表、Diff 过程等自定义组件，并明确版本与输入输出。先完成一个高价值实验组件，避免早期建设复杂插件平台。

重要产品约束：不要在 CourseX 新建独立的“知识库管理后台”和“学习记录中心”。知识、对话、引用的统一入口就是章节画布；必要的结构化字段服务于检索、链接与导出，而不是让用户填写更多表单。
05 / USER JOURNEY

新的学习流程：四步，不再打卡

保留独立思考与代码验证的严格性，但去掉每课强制执行的日程、Quiz 数量、面试追问与双套记录。复杂机制允许跨多次学习，不把效率指标建立在看完多少视频上。

STEP 01

提出问题

选章节，在画布上放一个问题或假设。

STEP 02

学习探索

看课件、读源码、问 AI，保存有价值的讨论。

STEP 03

独立验证

写 mini React、测试、最小实验，发现理解偏差。

STEP 04

画布沉淀

留下结论、引用与图解，需要时回头更新。

主流程 · 必需

学习的最小完成条件

你能够不依赖课件，用自己的语言解释核心机制，并至少通过一个可信的源码依据、测试或独立实验确认关键行为。画布留下能让未来的自己快速恢复理解的内容。

创作分支 · 按需

图解作品化不强制每节执行

只有当某个机制确实适合“操作后更容易理解”时，再将草图提升为交互原型。原型通过技术与教学审核后，才进入未来的公开教材。

# JSX Runtime

JSX 编译与 ReactElement 创建是两个环节。
ReactElement 仍不是宿主 DOM。

## 我的证据
- mini React 测试：evidence_jsx_test
- React 官方源码：指定版本及路径

导出行为与一致性规则

C01 · 一键导出
P0

提供“导出当前课程/全部学习数据”的操作。导出时获取一致性快照，并明确导出范围、生成时间和 schemaVersion。导出包包含知识正文与画布结构，不是只有图片或不可读的单一大 JSON。

C02 · Git 稳定性
P0

文件名/对象 ID 稳定，属性按固定顺序输出、换行统一、序列化排序稳定。时间戳等易变化字段限制在必要范围；未经修改的卡片反复导出不产生无意义 Diff。画布位置更新不应改写全部卡片的 Markdown。

C03 · 恢复验证
P1

支持导入同版本导出包，恢复章节主画布绑定、卡片、对话和布局；检查缺失资源/未知对象类型并给出错误报告。采用先预览再确认的导入方式，默认避免覆盖已有数据。

C04 · 安全与版权
P0

导出前提示敏感内容范围。默认不包含登录凭据、API Key、cookie、本地路径中的私密信息、付费课程原始视频/完整课件；对话导出应支持选取已保存片段。个人备份与公开分享须有清晰区分。

不能忽略的技术问题：如果 CourseX 当前只保存 tldraw 原生 JSON，应优先研究“结构化内容对象与 shape 的映射”，不要简单从任意形状文字反向解析知识卡片；否则后续 Git 导出、检索、跨章引用与内容复用都将不可靠。

08 / IMPLEMENTATION ROADMAP

研发里程碑：按依赖拆解，不预设不可靠工期

里程碑以验收结果为标准，避免为了一个新的“学习系统”长期开发而耽误 React 本身的学习。先文档、后关联、再沉淀、再导出与恢复。

M0 · 调研与冻结契约

确认 CourseX 的现有实现边界

检查课程和章节 ID、画板存储位置、tldraw 版本和快照接口、Pi Agent 对话持久化方式、当前本地保存机制。确定 schemaVersion、实体 ID 规则和既有画板兼容策略。

验收：形成代码审计清单、数据关系设计和不破坏旧画板的迁移方案。
M1 · Learning Hub 精简

先把说明书变成能用的三份文档

改写 README、roadmap、workflow；旧学习记录归档；不重写历史笔记，不再维护原静态 Hub 进度机制。

验收：从 README 可以定位 S01-L01，理解四步法，并找到 CourseX 里要打开的章节。
M2 · CourseX 章节画布 MVP

章节主画布与知识卡片

建立稳定绑定、画布自动恢复、文本卡片/问题卡片、证据引用与轻量验证标记；尽量延续现有 tldraw 画板。

验收：创建 → 编辑 → 刷新 → 切章 → 回来，卡片和布局一致。
M3 · AI 与画布联动

把课节问答沉淀到章节画布

保存对话片段、提炼草稿、追溯原会话和源课节。确保“主动筛选、可编辑、未经验证不自动晋升”。

验收：一次 JSX 课节问答可保存为卡片并重访。
M4 · Git 结构化导出

可读、稳定、完整的一键导出

设计 manifest、语义内容、画布快照与资源引用；编写确定性序列化、隐私排除与 schema 校验。

验收：导出的目录可读、可 commit；重复导出仅在真正改变内容时出现有效 Diff。
M5 · 强化与长期演进

恢复导入、跨章引用、可复用交互图解

依据真实使用反馈，补齐恢复能力、导航与跨章节链接。再考虑源码实验组件与未来 React, Explained. 的发布管线。

验收：可以无损恢复一次课程快照，并至少完成一个可验证的交互机制原型。
实施节奏建议：

M1 可以与 M0 并行；M2 必须先于 M3，M4 应与 M2 同步约束数据模型而不是等到最后再设计。每完成一个里程碑，就用当前 JSX 课程真实体验验收一次。

09 / ACCEPTANCE & RISKS

可执行的验收清单

这些是产品级测试场景，不是管理型学习打卡。勾选只是这份网页中的审阅工具，不会写入 CourseX 或 React Learning Hub 数据。

0 / 12 已确认

主要风险与处理原则

R1. 画布变成堆积信息的垃圾场
默认不自动将 AI 全部输出放到画布。以“保存片段 / 提炼卡片”的主动操作为主；在每章画布里提供适度的框架、聚焦、搜索与整理能力，但不强制模板化。
R2. tldraw 原始快照与语义数据不同步
稳定的内容实体 ID 与 shape 引用分离。写入顺序、事务边界、删除与恢复都应定义清楚；采用一次课程内容快照进行导出，保证关系有效。
R3. AI 错误被当作源码事实长期传播
来源可追溯、验证状态默认 draft、明确 React 版本和课程简化差异。对话和知识卡片分离，生成卡片必须经过用户确认。
R4. 复制课程原文造成版权与传播风险
课程资源只保留必要引用与用户原创笔记；不将付费原视频、完整课件、授权凭据或会话 cookie 纳入默认 Git 导出；公开教材进行独立表达与验证。
R5. 本地数据损坏、跨设备和覆盖冲突
MVP 先实现手动结构化导出；随后增加导入校验、备份检查、版本迁移、冲突预览。不要一开始建设双向自动 Git 同步，避免产生更难解决的冲突。
R6. 产品开发挤占 React 学习时间
以当前 JSX 章节验证实际收益，锁定 P0 范围；每次只做一项能减少学习摩擦的改进。不要提前建设课程管理后台、Agent 终端或完整互动教学编辑器。

衡量成效：不是“完成率”，而是学习能否持续

学习体验

更少重复整理

从打开课节到找回上次知识画布是否顺畅；是否无需额外维护另一个笔记/进度体系。

知识质量

可追溯、可纠错

关键结论是否链接实验或源码；回访旧章节时能否快速理解原思路与曾犯的错误。

资产独立性

导得出、还原得回

内容在编辑器之外可读，变更可被 Git 审阅，未来可以被新的教学项目提取利用。
